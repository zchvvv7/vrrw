# 一、研发目标

项目研发应形成可复现、可评估、可联调的完整软件与模型闭环。交付不能只包含模型权重或演示视频，必须同时提供数据说明、配置、代码、日志、评估结果、失败案例和部署文档。

# 二、技术基线

| 模块  | 建议基线 | 最低要求 |
| --- | --- | --- |
| 可行驶区域 | SegFormer、DeepLabV3+或BiSeNet类模型 | 输出像素掩码、边界及置信度 |
| 已知障碍物 | YOLO系列、RT-DETR类检测器或实例分割模型 | 重点验证小目标Recall |
| 未知异常 | 最大Softmax/能量分数、重建误差或异常分割网络 | 至少建立一个可复现基线 |
| 距离估计 | 单目深度、几何投影或仿真深度辅助 | 报告近距离误差 |
| 风险状态机 | 规则或轻量学习模型 | 可配置、可解释、有防抖 |
| 系统接口 | 结构化目标列表与风险报文 | 包含版本、延迟和降级状态 |

# 四、代码与工程规范

• 代码按数据、模型、训练、推理、评估、接口和仿真模块拆分。

• 全部参数进入YAML/JSON配置，禁止将路径、阈值和类别硬编码在核心逻辑中。

• 训练和评估记录Git提交、配置、数据版本、随机种子和运行环境。

• 大文件、数据集和权重不得直接提交Git；使用索引或受控存储。

• 关键模块提供单元测试；风险状态机和坐标转换必须覆盖边界条件。

• 异常退出、丢帧、传感器不可用和模型加载失败必须返回明确错误码。

# 八、验收门槛

• 全部P0功能可以在统一入口下运行。

• 从环境安装到推理评估具备完整可复现步骤。

• 真实数据与仿真数据均有结果，且明确两者差异。

• 未知障碍物即使无法分类，也能输出异常区域及空间风险。

• 相机严重退化时能够输出降级状态。

• 性能数据在目标GPU、固定分辨率和固定批量下测得。

• 报告包含失败案例和已知限制，不只展示最佳样例。
