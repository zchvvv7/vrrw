# 一、数据使用原则

• 所有数据集在下载前核验许可协议和研究用途限制。

• 原始数据只读保存，转换与预处理结果必须可由脚本重建。

• 训练集、验证集和测试集按序列或场景划分，防止相邻帧泄漏。

• 不同数据集必须先完成类别、忽略区域和坐标系映射，禁止直接无规则混合。

• 数据版本、来源、文件数量、校验值和处理脚本统一登记。

# 二、候选数据集

## 2.1 道路语义与可行驶区域

| 数据集 | 用途  | 注意事项 |
| --- | --- | --- |
| Cityscapes | 城市道路语义分割和可行驶区域基线 | 精细标注，但场景与天气范围有限 |
| BDD100K | 可行驶区域、车道和道路目标联合学习 | 适合真实视频与多任务基线 |
| Mapillary Vistas | 跨地域道路语义和泛化测试 | 类别丰富，需进行类别映射 |

## 2.2 异常与未知障碍物

| 数据集 | 用途  | 建议  |
| --- | --- | --- |
| Lost and Found | 道路小障碍物检测/分割 | 作为道路障碍物重点测试集 |
| Fishyscapes | 像素级异常检测 | 评估训练类别之外区域 |
| RoadAnomaly21 | 道路未知物体异常分割 | 用于异常分割验证 |
| SegmentMeIfYouCan | 异常分割与道路障碍物评测 | 统一比较未知物体能力 |

## 2.3 推荐最小组合

| 阶段  | 组合  | 目标  |
| --- | --- | --- |
| 基础分割 | Cityscapes或BDD100K | 跑通可行驶区域基线 |
| 异常检测 | 正常道路训练集 + Lost and Found | 建立未知障碍物基线 |
| 泛化评估 | Mapillary Vistas + Fishyscapes/RoadAnomaly21 | 跨地域和未知风险评估 |
| 闭环验收 | 真实数据 + CARLA合成数据 | 验证风险状态和极端场景 |

# 五、CARLA部署要求

## 5.1 基本要求

• 采用与服务器系统兼容的CARLA预编译发布包。

• CARLA Python API版本必须与服务端版本一致。

• 使用同步模式和固定时间步长保证图像、物理状态与真值对齐。

• 无显示器服务器采用离屏渲染，并完成连续帧稳定性测试。

## 5.2 最小连通性验收

| 步骤  | 验收结果 |
| --- | --- |
| 启动服务端 | 日志无致命错误，端口可连接 |
| 客户端连接 | 成功读取world和map |
| 生成自车 | 车辆稳定生成并可控制 |
| 挂载传感器 | RGB、深度、语义分割回调正常 |
| 同步采集 | frame_id一致并连续落盘不少于1000帧 |

# 六、仿真场景要求

| 场景  | 注入对象 | 变量  | 预期真值 |
| --- | --- | --- | --- |
| 施工改道 | 锥桶、护栏、施工车辆 | 布局、间距、天气、车速 | 封闭区域与可行驶区域 |
| 道路遗撒 | 纸箱、轮胎、木板或自定义资产 | 尺寸、颜色、距离、遮挡 | 障碍物实例、距离、占道比例 |
| 坑洼破损 | 道路材质或自定义资产 | 面积、深度、阴影、积水 | 路面风险区域 |
| 事故占道 | 静止车辆、散落物、警示牌 | 占用比例、弯道遮挡 | 冲突关系与风险等级 |
| 感知降级 | 暴雨、夜间、逆光、镜头退化 | 雨量、曝光、遮挡率 | degraded/unavailable |

# 七、Ground Truth导出要求

• 保存frame_id、仿真时间戳、地图、天气、随机种子和场景编号。

• 保存自车位姿、速度、加速度、转向角和预测行驶走廊。

• 保存每个障碍物Actor ID、类别、3D包围框、距离和车道占用。

• 同步输出RGB、语义分割、实例分割和深度。

• 保存风险真值：走廊交叠、TTC、风险等级和主要原因。

• 未知类别实验必须保证测试异常资产未以相同或近重复形式进入训练集。

# 八、仿真数据验收

| 检查项 | 通过条件 |
| --- | --- |
| 同步性 | 各传感器frame_id与物理状态严格对应 |
| 可复现性 | 相同配置和随机种子可重建场景 |
| 标注质量 | 2D/3D投影正确，无系统性坐标偏移 |
| 覆盖度 | 每类场景包含距离、速度、天气和遮挡组合 |
| 可用性 | 数据读取、可视化和评估脚本完整 |
